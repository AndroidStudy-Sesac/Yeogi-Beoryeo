# 품목 가이드 안정 ID 관리

품목 즐겨찾기는 표시명이 아니라 `id`를 영구 식별자로 사용한다. 표시명이나 자산 순서가 바뀌어도 저장된 즐겨찾기가 같은 품목을 가리켜야 한다.

## ID 규칙

- 형식은 `item-guide-NNNN`이다.
- 새 품목에는 사용한 적 없는 다음 번호를 배정하고 자산에 저장한다.
- 배열 순서나 표시명으로 실행 중에 ID를 만들지 않는다.
- 배정한 ID는 변경하거나 다른 품목에 재사용하지 않는다.
- 로컬 품목 사전과 대표 상세 가이드가 같은 상세 가이드 한 건을 가리키도록 설계된 경우에만 같은 ID를 사용한다.

## 상세 가이드 구분 기준

안정 ID는 넓은 분리배출 분류가 아니라 사용자가 저장하고 다시 여는 상세 가이드 한 건을 식별한다.

대표 카테고리 안내와 검색 품목 사전은 같은 분리배출 분류를 설명하더라도 표시명, 내용, 진입 역할이 다르면 서로 다른 ID를 사용한다. 다음 조합은 각각 대표 카테고리 안내와 검색 품목 사전에서 계속 사용하는 별도 상세 가이드다.

- `플라스틱류` / `플라스틱`
- `비닐류` / `비닐`
- `금속류` / `금속`
- `의류 및 원단` / `의류, 원단`

위 이름은 변경 전 표시명이 아니라 각 가이드의 현재 표시명이므로 `legacyNames`에 추가하지 않는다.

## 표시명 변경과 품목 통합

- 표시명만 바꿀 때는 ID를 유지한다.
- 변경 전 표시명은 해당 품목의 `legacyNames`에 계속 보존한다.
- 여러 품목을 하나로 통합할 때는 유지할 품목의 ID를 선택하고, 이전 표시명을 모두 `legacyNames`에 추가한다.
- 이미 배포한 다른 안정 ID를 통합해야 한다면 다음 DB migration에서 유지할 ID로 변환한다.
- 현재 표시명과 `legacyNames`는 전체 자산에서 하나의 ID에만 연결되어야 한다.

## 품목 삭제

- 삭제한 품목의 ID는 재사용하지 않는다.
- 더 이상 연결할 품목이 없는 즐겨찾기는 DB migration에서 품목 즐겨찾기만 삭제한다.
- 장소와 지역 가이드 등 다른 즐겨찾기 유형은 변경하지 않는다.

## 기존 즐겨찾기 변환

DB 3→4 migration은 표시명으로 저장된 품목 즐겨찾기를 자산의 안정 ID로 변환한다. 현재 표시명과 `legacyNames`를 모두 인식하며, 여러 이전 이름이 같은 ID로 합쳐지면 가장 최근 저장 시각을 유지한다. 자산에서 찾을 수 없는 품목 즐겨찾기만 삭제한다.
